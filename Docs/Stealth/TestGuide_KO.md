# 잠입 시험장 사용 설명서

대상: `Lvl_SPStealthTest` · UE 5.8.2 · 2026-10-08 한글 안내 기준.

이 맵은 한 번에 공략하는 완성 스테이지가 아니라 **기능을 하나씩 비교하는 시험장**이다. 구역 번호는 시험 종류를 알려주는 표지다. 구역을 옮긴다고 발각 상태가 자동으로 초기화되거나 이전 시험의 영향이 차단되지는 않는다.

## 먼저 알아야 할 세 가지 상태

| 상태 | 뜻 | 발생 예 |
|---|---|---|
| 플레이어별 신원 발각 | 경비가 **누가 범인인지** 안다. A가 발각돼도 B는 그대로다 | 제한 구역 침입/포장을 1초간 목격, 순간 범죄를 발생 순간 목격 |
| 익명 현장 수색 | 범인은 모르고 **어느 위치를 조사할지**만 안다 | 레이저 접촉, 작업 소리, 간접 신고 |
| 전체 경보 | 스테이지 전체의 보안 상태 | 직접 범죄 확인, 피해자 신고, 탈출 작동 사건 |

**경비가 뛰어온다고 무조건 발각된 것은 아니다.** 머리 위가 `사건 위치로 이동`이면 익명 조사이고, `발각자 추격 중`이면 확인한 플레이어를 쫓는 것이다. 왼쪽 상태창의 본인 `미발각/신원 발각`과 `전체 경보: 없음/발생`을 따로 본다.

이미 발각됐다면 일반 구역에서 정상 이동만 해도 그 신원을 공유하는 경비가 다시 보고 추격할 수 있다. 그래서 다음 독립 검사를 시작하기 전에 초기화해야 한다.

## 실행과 초기화

1. 콘텐츠 브라우저에서 `Content/SpacePirate/Maps/Lvl_SPStealthTest`를 연다.
2. 처음은 1인 Play로 해도 된다. 두 사람 비교는 플레이 설정에서 **플레이어 수 2 / 리슨 서버 / 단일 프로세스 실행**을 선택한다.
3. 화면에 `진행 중`, `전체 경보: 없음`, 모든 플레이어 `미발각`이 보이는지 확인한다.
4. WASD 이동, 마우스 시점, Shift 달리기, Ctrl 유지 앉기, Space 점프, E 상호작용, G 내려놓기/가방 던지기, 1~4/휠 슬롯 선택을 쓴다.
5. E 버튼은 글자 대신 **상자 본체**를 가까이서 조준한다. 조준 거리는 최대 약 250cm다. `유지`가 붙은 동작은 E를 놓으면 취소된다.

| 다시 시험하는 방법 | 초기화되는 것 | 그대로 남는 것 |
|---|---|---|
| 08-3 **보안 초기화** | 신원, 전체 경보, 확인 시간, 수색/추격, 레이저 회차·접촉 계수, 진행 중 작업 | 플레이어/경비 현재 위치, 인벤토리, 집은 물건, 이미 생성한 가방 |
| 08-2 **시험 종료** | 보안 상태를 지우고 감지 중지. 레이저 꺼짐 | 맵의 물건과 위치 |
| 08-1 **새 시험 시작** | 새 회차로 보안 초기화 후 감지 재개 | 맵의 물건과 위치 |
| Play 종료 후 다시 Play | 맵에 저장된 배치와 물건에서 새로 시작 | 에디터에 저장한 맵 자체 |

**처음 따라 할 때는 아래 검사마다 Play를 새로 시작하는 것이 가장 확실하다.** 경비가 이미 이동했거나 포장할 물건이 사라졌으면 08번만 눌러서는 원래 배치로 돌아오지 않는다. 제한 구역 한가운데에서 초기화하면 곧 다시 목격될 수도 있다.

## 지도와 권장 순서

좌표는 센티미터다. 아래 지도의 위쪽은 월드 **+Y**, 오른쪽은 **+X**다. 화면을 돌리면 보이는 좌우는 달라지므로 큰 **구역 번호**를 기준으로 찾는다. 에디터에서 확인하려면 표의 액터 이름을 아웃라이너에서 검색하고 F로 위치를 찾을 수 있다. 내부 액터 이름은 자동 검사와 연결을 위해 유지했다.

```text
                       북쪽 / +Y
 ┌────────────────┬────────────────┬────────────────┐
 │ 06 익명 사건   │ 07 발각·경보   │ 08 시험 제어   │
 │  강제 버튼     │  강제 버튼     │  초기화/종료   │ Y=2250~3300
 ├────────────────┼────────────────┼────────────────┤
 │ 05-1 앉기 빔   │ 05-2 점프 빔   │ 05-3 대기 빔   │ Y=1800
 │   안전 공간    │   안전 공간    │   안전 공간    │ Y=1450
 ├────────────────┴─────────┬──────┴────────────────┤
 │ 04 범죄 버튼·실제 포장    │                       │
 │ 벽 뒤 소리 / 09 수색 지점 │ 02 제한 구역          │
 │                          │ 순찰 경비 2명·엄폐물  │ Y=-1100~1100
 │ 01 일반 구역·시작 위치   │                       │
 │ 03 줍기·운반·포장 테이블 │                       │ Y=-850
 └──────────────────────────┴───────────────────────┘
                       남쪽 / -Y
```

권장 순서: **01 정상 행동 → 03 상호작용 → 04 실제 포장 목격 → 02 제한 구역 → 05 실제 레이저 → 06·07 강제 사건 → 08 중복/초기화**.

초록 바닥과 노란 바닥은 보기 위한 표시다. 빨간 공간의 **독립 제한 구역 볼륨**이 실제 침입 판정을 한다. 순찰 경로를 바꿔도 이 제한 구역이 자동으로 바뀌지 않는다.

## 01 일반 구역: 아무 범죄도 하지 않았을 때

- 위치: 시작 지점과 서쪽 초록 바닥. 정상 행동 표지는 (-1550,300). 검색: `Crime_PublicNormal_Sign`.
- 행동: 미발각 상태에서 경비 앞을 걷고, 달리고, 점프한다. 03에서 주운 가방을 들고 다시 이동한다.
- 정상 결과: **미발각 / 전체 경보 없음**. 경비가 본다는 이유만으로 추격하지 않는다.
- 이유: 일반 이동, 달리기, 점프, 가방 운반, 바닥 가방 줍기는 범죄로 등록하지 않는다. 일반 발소리 감지도 현재 기본 설정에서는 꺼져 있다.
- 주의: 실수로 빨간 제한 구역에 들어갔거나 이전 검사에서 이미 발각됐다면 같은 결과가 나오지 않는다.

## 03 기존 상호작용: 줍기와 포장은 다르다

- 위치: 남서쪽 테이블 (-1600,-850). 검색: `Interaction_Table`.
- 행동 1: 테이블의 물건/가방을 조준하고 E, 슬롯을 바꾸고 G로 내려놓는다.
- 정상 결과 1: 기존 인벤토리와 운반이 동작하며, **줍기·운반만으로 발각되지 않는다**.
- 행동 2: 포장 묶음을 조준하고 E를 2초 유지한다. 먼저 짧게 눌렀다 놓아 취소도 확인한다.
- 정상 결과 2: 완료 시 기존 묶음이 가방으로 바뀐다. 취소하면 완료되지 않고 범죄 작업 등록도 정리된다.
- 주의: **포장 작업 자체는 범죄**다. 이 테이블에서 경비에게 보이지 않으면 발각되지 않는다. 목격 검사는 경비가 배치된 04의 묶음으로 하는 것이 쉽다.

## 04 실제 목격: 일반 구역에서도 범죄를 보면 발각

먼저 새 Play로 시작한다. 관찰 경비는 (-1100,100)에 서서 북쪽을 본다. 검색: `Crime_ObserverGuard`.

### 실제 포장 묶음

1. (-1000,600)의 테이블 위 묶음을 찾는다. 검색: `Crime_PublicLootBundle`.
2. 경비의 시야에 보이는 상태로 묶음을 조준하고 E를 유지한다.
3. 약 1초 동안 작업하는 모습이 연속해서 보이면 머리 위가 `범죄 확인 중`에서 `발각자 추격 중`으로 바뀐다.
4. 상태창에 **행위자만 신원 발각 + 전체 경보 발생**이 표시된다. 2초 포장을 완료하면 실제 가방이 생긴다.
5. 새 Play에서 다시 시도해 1초 전에 E를 놓는다. 이후 그냥 서 있으면 작업 때문에 뒤늦게 발각되지 않아야 한다.

시야가 벽에 막히면 그 관찰자의 1초 확인 시간은 초기화된다. 단, 다른 경비가 계속 보고 있다면 그 경비의 확인은 계속될 수 있다. 앉기 자체는 투명화가 아니다.

### 노란 상자 다섯 개

일렬로 배치된 상자는 **범죄 행동을 발생시켜 실제 목격 규칙을 검사하는 임시 단말**이다. 실제 물건 탈취·금고 개방·기절 효과까지 완성된 장치는 아니다.

| 표지 | 위치 X / Y=1000 | 입력 | 발각 조건 | 실제 게임 효과 |
|---|---:|---|---|---|
| 04-1 소매치기 행동 시험 | -1800 | E 한 번 | 누른 순간 경비에게 보임 | 물건 탈취 미구현 |
| 04-2 보안 단말 행동 시험 | -1450 | E 3초 유지 | 작업 중 연속 1초 목격 | 단말 해킹 효과 미구현 |
| 04-3 금고 작업 행동 시험 | -1100 | E 3초 유지 | 작업 중 연속 1초 목격 | 금고 개방 미구현 |
| 04-4 포장 행동 시험 | -750 | E 3초 유지 | 작업 중 연속 1초 목격 | 가방 생성 없음. 실제 묶음은 별도 |
| 04-5 제압 도구 행동 시험 | -400 | E 한 번 | 누른 순간 경비에게 보임 | 기절 효과 미구현 |

순간 행동은 그 순간 안 보였다면 나중에 시야에 들어왔다고 소급 발각되지 않는다. 모든 E 상호작용을 범죄로 처리하는 것도 아니다.

### 04-6 벽 뒤 작업 소리

- 위치: 서쪽 높은 벽 뒤 (-2450,500). 검색: `Crime_WorkNoise`.
- 행동: 상자에 E를 누른다. 이 버튼은 실제 드릴 오디오를 듣는 검사가 아니라 **작업 소리 사건을 제출하는 시험 버튼**이다.
- 정상 결과: 전용 경비 1명이 벽 뒤 **(-2300,550,0)**으로 이동 → 5초 현장 수색 → 순찰 상태. 본인 신원과 전체 경보는 바뀌지 않는다.
- 수색 현장 옆에 정상 행동으로 서 있어도 추격하면 안 된다. 그곳에서 별도 범죄를 목격하거나 이미 발각된 사람을 발견하면 추격할 수 있다.

## 02 제한 구역: 들어간 즉시 경보가 울리는 것은 아니다

- 위치: 동쪽 붉은 바닥. 실제 범위 X=100~2700, Y=-1100~1100. 검색: `Restricted_Area_Main`.
- 행동: 미발각 상태에서 들어가 먼저 상태창의 `제한 구역` 표시를 확인한다. 순찰 경비 앞에 보이게 선다.
- 정상 결과: 구역 진입만으로는 신원이 발각되지 않는다. **경비가 침입자를 연속 1초 보면** 그 사람의 신원과 전체 경보가 확정된다.
- 엄폐 검사: 발각되기 전에 벽 뒤로 숨어 시야를 끊으면 확인 시간이 초기화된다. 다른 경비에게 노출되지 않았는지도 확인한다.
- 이미 발각된 뒤 숨기: 경비는 마지막 목격 위치로 가서 수색한다. 시야에서 사라져도 신원이 자동으로 지워지지 않는다. 다시 보이면 즉시 추격한다.
- 경비 공격·체포 완료는 미구현이다. 체력·다운·구조는 아래 별도 절차로 확인한다.

## 05 실제 레이저: 상자 버튼 대신 몸으로 통과

세 구간의 빔은 모두 Y=1800이다. 각 구간 앞 Y=1450의 초록 안전 공간에서 시작해 **북쪽으로** 통과한다. 빔 양끝을 돌아갈 수 있는 시험 배치이므로 기능을 보려면 **두 장치 사이의 빔을 직접 가로지른다**.

| 구간 | 중심 X | 안전하게 통과하기 | 일부러 감지시키기 |
|---|---:|---|---|
| 05-1 앉기 · 높이 145cm | -2100 | 안전 공간에서 먼저 Ctrl 유지 → 끝까지 앉아 이동 | 서서 걷기 |
| 05-2 점프 · 높이 40cm | 0 | 걷다가 빔 약 120cm 앞에서 Space, 빔을 넘을 때까지 전진 | 점프 없이 걷기 |
| 05-3 꺼짐 대기 · 높이 95cm | 2100 | 파란 빔의 `꺼짐 · 통과 가능`이 된 직후 걷기 | 빨간 빔이 켜져 있을 때 걷기 |

현재 플레이어는 서기 캡슐 높이 192cm, 앉기 높이 112cm다. 앉은 캡슐의 바닥 여유를 포함한 상단은 약 114cm다. 기존 점프 설정으로 40cm 빔을 실제 통과 확인했다. 달리기 점프가 아니라 **일반 걷기에서의 점프**를 먼저 시험한다.

대기 구간은 켜짐 4초 + 꺼짐 4초이며 각 전환 전 1초 동안 노랗게 예고한다.

- `켜짐 · 접촉 위험`: 감지함.
- `곧 꺼짐 · 아직 위험`: 노란색이지만 여전히 감지함.
- `꺼짐 · 통과 가능`: 감지하지 않음.
- `곧 켜짐 · 통과 주의`: 아직 꺼져 있지만 곧 켜짐. 처음 검사는 이때 출발하지 않는다.

**감지되었을 때의 정상 결과:** 레이저 전용 경비 1명이 해당 발신 장치의 바닥 원점으로 이동하고 현장 수색한다. 접촉자의 신원을 전달하지 않으므로 **미발각 / 전체 경보 없음**을 유지한다. 경비 목적지는 플레이어를 따라 갱신되지 않는다.

빔 안에 서 있는 동안 켜져도 감지한다. 계속 닿아 있는 것은 같은 사건으로 묶고, 나갔다 다시 들어오면 새 사건이다. 같은 장치의 새 호출은 기본 2초 간격을 지키므로 재진입 직후 경비 반응이 늦을 수 있다. 다른 장치는 별도 사건이다.

## 06 익명 사건과 09 수색 목적지

06은 북쪽 서편 방이다. **이곳의 ‘레이저 사건’ 상자는 빔 센서가 아니다.** E 완료 시 사건을 직접 제출해서 대응 정책만 검사한다. 실제 접촉 검사는 05를 사용한다.

| 버튼 | 위치 (X,Y) | 호출 위치와 기대 결과 |
|---|---|---|
| 06-1 레이저 사건 강제 발생 | (-2550,2250) | (550,-800,0). 같은 그룹 경비 조사, 신원·경보 변화 없음 |
| 06-2 작업 소리 사건 | (-2100,2250) | 위와 같음 |
| 06-3 간접 신고 사건 | (-1650,2250) | 위와 같음. 실제 기절한 사람/열린 금고 검사기는 후속 범위 |
| 06-4 현장 조사 호출 | (-2400,2900) | **09 바닥 표시 (-650,600,0)**로 경비 1명. 도착 후 5초 수색하고 복귀 |
| 06-5 도달 불가 호출 | (-1800,2900) | **09 공중 표시 (-650,600,900)**로 경비 1명. 완전 경로가 없으면 최대 3회 시도 후 실패를 기록하고 복귀 |

06-4를 누른 뒤 경비가 버튼 상자로 오지 않는 것이 정상이다. **버튼 위치와 사건 위치를 의도적으로 분리**했다. 09는 목적지 표시이며 공중 원통은 올라서는 발판이 아니다.

경비가 이미 직접 확인한 사람을 추격 중이면 익명 호출을 무시할 수 있다. 먼저 보안 초기화하거나 새 Play로 검사한다.

## 07 직접 발각·전체 경보 강제 시험

북쪽 중앙 방이다. 이 버튼들은 **경비가 보지 않아도 결과를 강제로 제출**한다. 실제 시야 감지를 확인하려면 02 또는 04를 쓴다.

| 버튼 | 입력 | 신원 | 전체 경보 |
|---|---|---|---|
| 07-1 지속 범죄 강제 목격 | E 1초 유지 | 누른 본인 발각 | 발생 |
| 07-2 순간 범죄 강제 목격 | E 한 번 | 누른 본인 발각 | 발생 |
| 07-3 직접 목격 신고 완료 | E 2초 유지 | 누른 본인 발각 | 발생 |
| 07-4 피해자 신고 | E 한 번 | 변화 없음 | 발생 |
| 07-5 발각자 재발견 | E 한 번 | 이미 발각된 본인만 처리. 미발각이면 거부 | 새 경보를 만들지 않음 |
| 07-6 탈출 작동 사건 | E 한 번 | 변화 없음 | 발생 |

07-6은 탈출 성공/스테이지 완료/열차 정차를 구현한 버튼이 아니다. **탈출 장치가 작동했다는 보안 사건**만 시험한다. 07-3도 실제 민간인의 신고 행동·방해·애니메이션 전체를 재현하지 않는다.

## 08 중복 처리와 두 플레이어 비교

북쪽 동편 방이다. 첫 줄은 새 시험 시작/시험 종료/보안 초기화, 둘째 줄은 마지막 버튼 사건 반복이다.

1. 새 Play에서 A만 07-2를 누른다. A는 `신원 발각`, B는 `미발각`, 전체 경보는 `발생`이어야 한다.
2. 08-4를 누른다. `중복 사건 · 추가 처리 없음`이 뜨고 최초 발생 횟수가 늘지 않아야 한다.
3. 08-3으로 보안을 초기화한다. 양쪽 창에서 모두 `미발각 / 전체 경보 없음`으로 돌아와야 한다.
4. 07-4를 누른다. 두 사람 모두 미발각인 채 전체 경보만 발생해야 한다.
5. 초기화 후 05의 실제 빔을 한 사람이 통과해 감지시킨다. 양쪽 창의 빔 상태와 경비 상태, 두 사람의 미발각 표시가 일치해야 한다.

08-4는 **마지막 개발용 사건 버튼**을 반복한다. 실제 레이저 접촉이나 실제 포장 목격을 재생하는 버튼이 아니다. 초기화 후 옛 사건을 다시 보내면 `이전 회차 사건 · 무시됨`이 정상이다.

## 경비와 화면 표시 읽기

| 머리 위 표시 | 동작 |
|---|---|
| 순찰 중 | 경로가 있으면 순찰. 시험용 정지 경비는 경로가 없어 그 자리에서 대기 |
| 범죄 확인 중 | 침입/지속 범죄를 보고 1초 확인 중 |
| 사건 위치로 이동 | 범인 신원 없이 받은 위치로 조사 이동 |
| 현장 수색 중 | 익명 위치 도착 후 기본 5초 수색 |
| 발각자 추격 중 | 직접 확인했거나 이미 알려진 플레이어를 추격 |
| 마지막 목격 위치로 이동 | 추격 대상이 시야에서 사라져 마지막 좌표로 이동 |
| 마지막 목격 위치 수색 | 마지막 좌표 주변 수색 후 순찰 복귀 |
| 소리 확인 중 | 선택적 기존 발소리 기능. 현재 맵에서는 기본 비활성 |

경비는 4명이다. 제한 구역 순찰 2명, 04 범죄 관찰/작업 소리 대응 1명, 05 레이저 대응 1명이다. **출동 담당 그룹은 나뉘지만 발각된 신원은 공유한다.** 한 번 발각된 플레이어가 다른 시험 구역으로 이동한다고 안전해지는 것은 아니다.

상태창의 `최초 발생: 발각 n회 / 경보 n회`는 현재 회차의 최초 효과 수다. 경보가 이미 발생한 상태에서 같은 사건을 다시 처리해도 경보 횟수는 증가하지 않는다. A와 B가 각각 처음 발각되면 발각 횟수는 2가 될 수 있다.

## 체력·다운·구조 통합 시험

두 사람이 **01 일반 구역**에서 시작한다. H로 한글 디버그 도움말을 열고 닫을 수 있다. 경비 공격은 아직 없으므로 F6/F7이 시험용 피해 입력이다.

1. A가 F6을 누르면 자신의 체력이 25 감소하고 B는 그대로다. F7을 누르면 A가 다운되어 이동·작업을 할 수 없다.
2. B가 가까이에서 A의 몸을 바라보고 E를 4초 유지하면 A가 체력 30으로 구조된다. E를 놓거나 이동하면 진행이 0으로 돌아간다.
3. **04 포장 대상**을 E로 포장하는 도중 F7을 누르면 포장 진행과 범죄 등록이 즉시 취소된다. 작업이 저절로 끝나 가방을 생성하면 안 된다.
4. 먼저 목격으로 A만 발각시킨 뒤 다운/구조하면 A의 발각은 유지되고 B는 미발각이다. 구조는 위장을 회복시키지 않는다.
5. 두 사람이 모두 F7로 다운되면 양쪽 화면에 작전 실패가 표시된다. **호스트 Shift+F7**은 체력·작전 실패·개인 발각·전체 경보와 경비 대응을 함께 초기화한다.

시험 단말의 **보안 초기화**는 체력/다운/작전 실패를 바꾸지 않는다. 두 초기화 모두 이미 포장한 물건이나 가방, 플레이어 위치는 복원하지 않는다. 완전한 처음 상태가 필요하면 Stop 후 Play한다. 별도 회귀 검사와 실제 수행 결과는 [검증 절차](Testing.md), [병합 결과](MergeReview.md)에 있다.

## 예상과 다르게 보일 때

| 증상 | 먼저 확인할 것 |
|---|---|
| 일반 구역에서 경비가 쫓아옴 | 본인이 이미 발각됐는지, 포장 중인지, 빨간 제한 구역에 걸쳤는지 |
| 포장했는데 발각되지 않음 | 경비의 실제 방향·거리·엄폐. 1초 연속 시야를 확보했는지 |
| 재시작 버튼을 눌러도 묶음이 안 돌아옴 | 보안만 초기화하는 버튼이다. Play 종료 후 다시 시작 |
| 사건 버튼을 눌렀는데 경비가 버튼으로 안 옴 | 버튼 위치와 사건 목적지는 다르다. 06 표의 좌표/09 표시 확인 |
| 레이저를 건드렸는데 발각되지 않음 | 정상이다. 익명 위치 조사만 유도한다 |
| 노란 빔에서 감지됨 | `곧 꺼짐`은 아직 켜짐이다. 색뿐 아니라 상태 문자 확인 |
| 경비가 ‘순찰 중’인데 가만히 서 있음 | 04/05의 정지 관찰 경비에는 순찰 경로가 없다 |
| E가 안 됨 | 상자/물건 본체 조준, 250cm 이내 접근, 유지 시간, 다른 사람 사용 여부 |

## 현재 구현 범위와 개발 문서

실제로 구현한 것은 이동·운반·포장, 독립 제한 구역, 공통 시야/범죄 판정, 개별 신원/전체 경보, 익명 조사/수색/실패 복귀, 실제 레이저와 상태 복제다. 임시 상자의 금고·소매치기·제압·탈출 문구는 **그 보안 사건이나 행동 종류를 시험한다는 뜻**이며 전체 게임 효과의 완성을 뜻하지 않는다.

개발 연결과 수행 결과는 [ImplementationStatus.md](ImplementationStatus.md), 애셋 교체는 [AssetManifest.md](AssetManifest.md), 실제 레이저 설정은 [LaserSecurity.md](LaserSecurity.md)에 있다. 한글화 작업의 검증 결과도 구현 상태 문서에 별도로 기록한다.
