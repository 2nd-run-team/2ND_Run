# 기획안 1 프로토타입 애셋 목록

애셋은 플레이어가 화물, 위험, 경로, 탈출 상태를 읽는 데 필요한 순서로 준비한다. 기본판은 기존 열차와 캐릭터를 활용하고, 새로 필요한 장치와 피드백을 먼저 만든다. 아래 수량은 배치 개수가 아니라 **제작할 원형 또는 표현 종류의 최소 제안**이다. 예를 들어 일반 화물 원형 4종을 40개 배치한다.

이 문서는 필요한 표현을 정의한 목록이다. 이후 추가된 보유 팩의 실제 폴더와 활용·대체 지침은 [보유 애셋 우선 활용 지침](asset-usage-instructions.md)을 따른다. 사용 가능한 기존 에셋의 라이선스·원본 출처는 팀 보유 기록으로 확인하고, 외부 팩은 실제 5.8.2 로드와 충돌을 확인한 뒤 채택한다. 에셋을 추가하기 위해 프로젝트 엔진 버전을 바꾸지 않는다.

## 1 기존 자산 재사용

| 자산 | 현재 경로 | 사용할 부분 | 확인할 부분 |
|---|---|---|---|
| 열차 편성 | `/Game/SpacePirate/Train/Freight/Blueprints/BP_SPTrainConsist` | 고정 편성의 차량과 연결 통로 | 10칸 배열, 출입구, 자식 컴포넌트 충돌 |
| 차량 5종과 데이터 | `Train/Freight/Blueprints/BP_SPFreightCar_*`, `Train/Freight/Data/DA_SPCar_*` | 넓이·길이가 다른 객차 골격 | 실제 실내 폭, 천장, 문, 회전·중력 복귀 공간 |
| 열차 메시와 재질 | `/Game/SpacePirate/Train/Freight/Meshes`, `Materials`, `Textures` | 차체·바닥·벽·유리·조명·연결부 | 카메라 가림, 캐릭터 통과, 투명 재질 비용 |
| 배경과 하늘 | `/Game/SpacePirate/Train/Systems/TrainEnvironment`, `Train/Environment` | 고정 열차 주행감과 우주 배경 1개 | 실행 중 하늘 전환은 평가판에 불필요 |
| 플레이어 | `/Game/SpacePirate/Player/Blueprints/BP_SPPlayerCharacter` | 기존 메시·이동·시점 | 다른 플레이어 식별 색, 자식 BP 연결 |
| 운반 표현 | `/Game/SpacePirate/Cargo/ABP_CargoCarry`, `AS_CargoCarryPose` | 선택 N01 실험의 운반 포즈 후보 | 스켈레톤, 소켓, 손/화물 겹침. 기본판 필수 아님 |
| 중력 영역 | `/Game/SpacePirate/Gravity/Blueprints/BP_SPGravityZone` | 객차 단위 중력 판정 | 연결 통로와 인접 영역 우선순위 |

위 표의 축약된 `Train/...` 경로는 `/Game/SpacePirate/Train/...`을 의미한다. 전체 TrainFreight 에셋 목록은 `Docs/TrainFreight/asset-paths.json`을 기준으로 조회한다. 기존 화물 BP는 Small/가치 0 기본값이므로 그 자체를 완성된 보급 화물로 간주하지 않는다.

## 2 기본판 필수 제작물

P0는 기믹 배치 전에 필요한 원형, P1은 외부 플레이테스트 전에 필요한 표현을 뜻한다. 개발 단계 P0~P7과는 다른 애셋 우선순위 표기다.

사운드 표는 효과·환경음 22개 기능 큐와 선택 음악 1개의 제안이며 원본 음원은 편집·변형으로 공유할 수 있다. 사람 목소리로 된 안내나 성우 녹음은 초기 필수가 아니다. 직접 녹음한 테스트 안내를 사용해도 된다.

## 5 제작 및 임포트 기준

- 길이 단위는 cm다. 기존 캐릭터 캡슐 기본 반경 34cm/반높이 96cm를 참고하되 실제 BP와 포즈로 확인한다.
- 넓은 통로는 유효 폭 약 180cm 이상을 첫 기준으로 두고, 2인 교차와 4인 정비·탈출을 실제로 테스트한다. 기존 기차 전체를 임의로 늘리지 않는다.
- S01으로 접근하는 천장 화물은 중력 상태의 250cm 확보 거리에서 미리 확보되지 않는지 확인한다. 카메라 높이를 포함해 측정한다.
- 문·카메라·패널은 움직일 부품과 고정 부품을 분리하고 피벗을 실제 회전·슬라이드 축에 둔다.
- 캐릭터 충돌, 시야 가림, 확보 트레이스가 의도대로 동작하는 단순 충돌을 먼저 작성한다. 장식 메시의 보이지 않는 충돌로 통로를 막지 않는다.
- 배경 장식과 확보 가능한 화물은 실루엣·표시등·아이콘으로 구분한다. 발광 색만 다른 같은 상자 네 종류로 끝내지 않는다.
- 기본판의 화물은 Simulate Physics를 사용하지 않는다. 선택 포드는 서버 드롭과 기존 운반 로직을 검증한 뒤 적용한다.
- 새 주요 소품은 우선 1K 텍스처로 시험하고 가까이 보는 표면만 2K를 검토한다. 모든 물체에 4K를 배정하지 않는다. 이는 시작 예산이며 실제 GPU 측정으로 조정한다.
- 한글 글꼴의 라이선스와 글리프를 확인한다. 1080p에서 값·진행·중단 이유가 겹치지 않아야 한다.
- 외부 에셋은 원본 폴더를 보존하고 프로젝트용 BP/MI는 Prototype01 아래에서 만든다. 모든 제작물은 LFS 정책과 경로 규칙을 따른다.
- 각 외부 애셋에 출처, 라이선스/취득 기록, 원본 버전, 실제 사용하는 파일, 담당자를 기록한다. 상품 구매나 다운로드는 별도 요청 때 진행한다.

첫 아트 적용의 완료 기준은 ‘고급스럽게 보임’보다 **어느 물건을 확보할 수 있고, 어떤 위험이 있으며, 어디로 나가야 하는지 플레이어가 알 수 있음**이다.
