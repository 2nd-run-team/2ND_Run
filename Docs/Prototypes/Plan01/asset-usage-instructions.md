# 기획안 1 — 보유 애셋 우선 활용 지침

작성일: 2026-10-01 · 대상: SpacePirate / Unreal Engine 5.8.2

이 문서는 기획안 1을 구현하는 코덱스 AI에 전달하는 작업 지침이다. **이미 추가한 애셋을 먼저 조사해 활용하고, 필요한 외형·효과가 없거나 적용 비용이 지나치게 크면 기본 도형과 재질로 직접 보완한다.** 애셋 부족을 이유로 구현을 멈추거나 추가 상품 구매를 선행 조건으로 삼지 않는다.

기능 범위와 수치는 [제작 계획서](prototype-plan.md), 진행 단계는 [개발 프롬프트](codex-prompts.md), 필요한 표현 종류는 [애셋 목록](asset-list.md)을 따른다. 애셋 선택·대체 방식에는 이 문서를 함께 적용한다. 이 지침 자체는 모든 개발 단계를 한 번에 실행하라는 뜻이 아니다.

## 1. 코덱스에 전달할 실행 프롬프트

```text
E:/GitHub/2ND_Run/SpacePirate.uproject에서 기획안 1을 개발한다.
Docs/Prototypes/Plan01/asset-usage-instructions.md를 읽고 이번 구현에 적용하라.
prototype-plan.md, asset-list.md, codex-prompts.md와 현재 implementation-status.md도 확인하라.

현재 요청받은 개발 단계에 필요한 외형·효과·사운드는 Content/Assets의 보유 애셋을
먼저 확인해서 사용하라. 적합한 메시나 효과가 있는데 같은 용도의 임시 큐브부터 만들지 마라.
기존 열차·플레이어·이동·중력 구현을 재사용하고, 기존 작업 중 변경을 보존하라.

애셋을 검토한 뒤 적절한 것이 없거나 기능·크기·충돌·성능·의존성 문제로 사용하기
어려운 부분은 기본 도형, 간단한 재질, 위젯과 필요한 최소 효과로 직접 보완하라.
일상적인 선택과 보완은 자율적으로 진행하고, 추가 구매나 다운로드를 요구하지 마라.
애셋이 있다는 이유로 기획에 없는 전투·가방 운반·CCTV 조작 기능을 추가하지 마라.

외부 팩의 원본은 참조해서 사용하고, 수정할 BP·재질 인스턴스·효과·사운드 설정은
/Game/SpacePirate/Prototype01 아래에 만들어라. 파일 시스템에서 uasset를 복사하거나
이름을 바꿔 참조를 깨뜨리지 마라. 에디터의 지원 기능으로 생성·복제하라.

파일 이름만 보고 작동 방식이나 호환성을 확정하지 말고 실제 로드와 구조를 확인하라.
기존 BP가 기획과 맞으면 필요한 부분을 재사용하고, 불필요한 의존성이 크면 메시·재질·음원만
활용해 기획안 1용 장치를 구성하라. 게임 판정은 서버가 담당하고 VFX와 사운드는 그 상태를 표현하라.

관련 에셋 로드·BP 컴파일·플레이 확인을 수행하고, 실행하지 못한 검증은 명확히 보고하라.
완료 시 사용한 원본 경로, 적용한 기능, 직접 제작한 부분과 이유, 검증 결과를
Docs/Prototypes/Plan01/implementation-status.md에 기록하라.
```

새 채팅에서는 이 프롬프트와 구현할 단계 프롬프트를 함께 전달한다. 이미 구현 중인 채팅에는 이 지침을 추가하고 현재 단계부터 적용한다. 완료된 모든 단계를 다시 만드는 작업으로 해석하지 않는다.

SuperGrid는 현재 `Content` 파일 검색에서 확인되지 않았다. 설치되어 있다고 가정하거나 필수 의존성으로 삼지 않는다. 이후 실제로 발견되면 경사로·발판의 후보로 사용할 수 있다. 기존 우주 배경과 열차는 프로젝트 자산을 우선 재사용한다.

## 3. 기능별 적용 규칙

### 화물과 자동 전송

- 외형과 판정을 분리한다. 화물의 가치·확보 시간·팀 점수·재확보 방지는 기획안 1 로직이 관리하며, 외부 상자 BP가 이를 대신한다고 가정하지 않는다.
- 일반 화물은 물리 시뮬레이션 없이 배치한다. 상자 열기, 내용물 하나씩 집기, 가방 넣기를 필수 과정으로 추가하지 않는다.
- 획득 가능한 화물에는 일관된 아이콘·이름·상호작용 표시를 사용한다. 같은 메시를 장식으로 쓸 경우 획득 표시를 없애고 배치·재질로 구분한다.
- 일반 코어 화물과 S01 중력 교란기는 형태와 아이콘을 구분한다. S01은 고유한 받침·링·중앙 코어 조합을 사용하고, 확보하면 중력이 바뀐다는 표시를 제공한다.
- 전송은 시작·진행·완료·취소가 구별되어야 한다. 완료 표현은 서버의 확보 확정에 맞춘다. 중단했는데 완료음이나 소멸 효과가 나오지 않게 한다.

### 감시 카메라

- 우선 기존 메시와 BP의 컴포넌트·회전축·입력·플레이어 참조·SceneCapture 사용 여부를 확인한다. 메시의 고정 베이스와 헤드가 분리되어 있다고 단정하지 않는다.
- 외형을 재사용하되 탐지·경고·피해·재사용 대기시간은 기획안 1 설계값을 따른다. 단일 플레이어 참조에 의존한 탐지를 그대로 채택하지 않는다.
- 보유 메시가 일체형이면 합리적인 축으로 전체를 회전시키거나 기본 도형 받침을 추가한다. 회전 표현이 부적합한 경우에만 도형 헤드로 대체하고 이유를 기록한다.
- 탐지 방향과 범위는 표시와 실제 판정이 일치해야 한다. 벽·엄폐 뒤의 플레이어에게 시야가 닿는 것으로 처리하지 않는다.
- CCTV 조작용 테스트 플레이어, 별도 HUD, 불필요한 실시간 모니터 렌더링을 프로토타입 플레이어에 이식하지 않는다. 관련 기능이 필요 없으면 활성화하지 않는다.

### 레이저와 문

- 보유 레이저 효과를 먼저 미리 보고 시작점·끝점·두께·반복·정지 방법을 확인한다. 파라미터 이름을 추측해서 연결하지 않는다.
- 보유 발진기 메시가 맞으면 사용한다. 맞지 않으면 큐브·실린더로 발진기만 보완하고 빔은 기존 VFX를 활용한다.
- 빔은 예고·작동·꺼짐 상태를 표현한다. 실제 피해는 별도 서버 판정으로 관리하며 VFX의 외형만으로 충돌이 생긴다고 가정하지 않는다.
- 문은 보유 문짝·문틀을 먼저 사용하고, 개폐 조건만 프로토타입 규칙에 연결한다. 열린 문에서 후발 플레이어의 합류가 막히지 않아야 한다.
- 크기 조절로 문·열차 충돌이 어긋나면 프로젝트용 충돌 또는 부품 구성을 수정한다. 맞추기 위해 열차 전체 크기를 임의로 바꾸지 않는다.

### 사운드 배정

아래 이름은 `InterfaceAndItemSounds/Cues`에서 확인한 파일명 계열이다. 재생 길이와 음색을 청취한 뒤 실제 선택 파일을 기록한다.

| 게임 이벤트 | 먼저 확인할 계열 | 적용 기준 |
|---|---|---|
| 버튼·패널 조작 | `Click`, `Futuristic_Click`, `Flick_Switch` | 누름·해제 상태 변화에만 짧게 재생. 프레임마다 반복하지 않는다. |
| 화물 확보 진행 | `Bar_Filling`, SciFiUISFX의 톤 계열 | 완료 시간에 맞는 재생인지 확인. 루프가 아니면 짧은 간격 신호로 사용하거나 최소 효과를 제작한다. |
| 확보 완료·점수 획득 | `Item_Sell_Purchase`, `Coins`, `Abstract_Pop` | 반복 청취해도 피로가 적은 한 가지 계열 선택. 금전 거래 기능을 추가하는 뜻은 아니다. |
| 취소·사용 불가 | `Back_Click`, `Error_Buzz` | 단순 취소와 실패·사용 불가를 다른 강도로 표현한다. |
| 위험·남은 시간 경고 | `Futuristic_Alarm`, SciFiUISFX의 링·톤 | 카메라 발각과 탈출 카운트다운을 구분한다. 동시 경보가 서로 묻히지 않게 한다. |
| 중력 전환·특수 화물 | `Special_Powerup`, SciFiUISFX의 FX·글리치 | 상태 전환 한 번에 연출 한 번. 일반 획득음과 구별한다. |
| 탈출 성공·실패 | `Special_Musical`, `Discordant_GameOver_Musical_Short` | 실제 음색을 확인해 선택. 플레이를 방해하는 긴 소리는 줄이거나 다른 후보를 사용한다. |

- 개인 UI 음과 월드 장치 음을 구분한다. 월드 음은 위치와 거리에 맞게 들리도록 설정한다. 호스트에서 로컬 처리와 복제 이벤트가 중복 재생되지 않는지 확인한다.
- 진행·장치 루프는 취소·완료·액터 제거·라운드 재시작 때 정지해야 한다. 동시 전송에서도 소리가 무제한 누적되지 않게 한다.
- CCTV의 `Sounds/Wav_Electricity`, `Wav_Static_CCTV`, `Wav_Fix`도 장치 효과 후보로 청취할 수 있다. 이 파일들이 열차 환경음·발소리·문 구동음을 모두 충족한다고 가정하지 않는다.
- 환경·동작 음원이 없으면 기존 프로젝트에서 먼저 찾는다. 그래도 없으면 구현 환경에서 지원하는 간단한 합성음·노이즈·가용 음원 변형으로 임시 피드백을 만들고 임시임을 기록한다. 적절한 발소리 원음이 없으면 무관한 UI음을 모든 발걸음에 붙이지 말고 해당 미보완 항목을 기록한 뒤 다른 구현을 진행한다.

## 4. 부족한 부분을 만드는 방법

선택 순서는 **이미 적용된 적합한 프로젝트 자산 → 보유 팩의 적합한 자산 → 보유 자산의 조합·프로젝트용 변형 → 기본 도형·간단한 재질 제작**이다. 기존 임시 도형도 보유 애셋으로 바꿀 이점이 있으면 현재 단계에서 교체한다. 성능·가독성·기능상 부적합한 애셋을 억지로 넣을 필요는 없으며, 모든 팩을 반드시 한 번씩 사용할 필요도 없다.

| 부족한 항목 | 기본 도형·재질 보완안 | 완료 기준 |
|---|---|---|
| 협동·단독 우회·정비·부활·탈출 패널 | 큐브 몸체 + 평면 화면 + 버튼 + 위젯 | 공통 원형 하나에 이름·아이콘·진행·상태를 바꿔 재사용한다. 조명 패널을 조작 패널로 오인하지 않게 한다. |
| S01 고유 외형 | 보유 상자/받침 + 구·실린더·링 형태 부품 + 보유 은하 재질 | 일반 화물과 다른 실루엣, 중력 변화 경고, 전송 후 변화가 보인다. |
| 선반·엄폐물 | 보유 상자와 복도 부품, 부족한 지지대는 큐브 | 화물 조준을 막지 않으며 시야 차단과 캐릭터 충돌이 의도와 일치한다. |
| 경사로·발판 | 엔진 기본 메시 또는 에디터 모델링으로 만든 쐐기·박스 | 실제 플레이어가 걷기·점프·복귀할 수 있다. 새 사다리 시스템은 추가하지 않는다. |
| 레이저 대체 표현 | 얇은 실린더/평면 + 발광 재질, 양끝 발진기 | 보유 VFX가 부적합한 경우에만 사용. 표시 두께·길이와 실제 위험 영역을 맞춘다. |
| 카메라 감지·피해 예고 | 반투명 범위 메시 또는 바닥 표시 + 경고 아이콘 | 엄폐와 방향을 읽을 수 있고 연출이 시야를 과도하게 가리지 않는다. |
| 전송·중력 전환 | 보유 효과 일부 또는 간단한 발광 변화·축소·소량 입자 | 시작과 완료를 구분하며 4명 동시 사용에서도 화물과 통로가 보인다. |
| 객차·탈출·플레이어 식별 | 평면·데칼·UMG + 글자·번호·색 | 색만으로 구분하지 않는다. 탈출 표식은 실제 판정 영역과 일치한다. |

첫 적용은 단순한 불투명 재질과 발광·색·러프니스 조절로 충분하다. 고해상도 텍스처나 복잡한 셰이더 제작을 필수로 두지 않는다. 효과가 부족하다는 이유로 전용 플러그인·대형 프레임워크부터 추가하지 않는다.

## 5. 원본과 프로젝트용 자산 관리

- 외부 원본 폴더 `/Game/Assets`의 경로와 이름을 유지한다. 원본 메시·텍스처·음원은 직접 참조하고, 실제 수정이 필요한 자산만 에디터에서 파생·복제한다. 팩 전체 복제를 기본 방식으로 삼지 않는다.
- 프로젝트용 콘텐츠는 `/Game/SpacePirate/Prototype01` 아래 기존 구조를 먼저 확인하고 `Blueprints`, `Materials`, `VFX`, `Audio`, `UI` 등에 역할별로 배치한다. 이미 같은 역할의 BP·MI가 있으면 새 중복 자산보다 기존 것을 확장한다.
- 예시 이름은 `MI_SP1_Cargo_Supply`, `MI_SP1_S01_Core`, `SC_SP1_CargoComplete`처럼 역할을 드러내도록 한다. 이 예시는 이미 존재하는 자산 경로가 아니다.
- 외부 팩의 데모 맵·테스트 캐릭터·GameMode·입력 설정으로 프로젝트 기본값을 교체하지 않는다. 프로젝트 엔진 버전은 5.8.2를 유지한다.
- 새 폴더로 가져온 자산은 이전 패키지 경로를 참조할 수 있다. 실제 로드와 의존성을 점검하고 누락을 보고한다. `Content/Movies`, `__ExternalActors__`, `__ExternalObjects__`는 불필요해 보인다는 이유로 삭제·이동하지 않는다.
- `.umap`/`.uasset` 편집에는 `CONTRIBUTING.md`의 LFS 잠금 규칙을 따른다. 다른 작업자의 변경·잠금을 덮어쓰지 않는다. 문서 작성만으로 게임 파일을 변경할 필요는 없다.

## 6. 적용 순서와 완료 확인

현재 개발 단계에 해당하는 항목만 수행하되, 필요한 기능은 끝까지 연결한다.

1. 현재 구현과 작업 트리를 읽고, 이번 단계의 화물·장치·효과별로 보유 후보를 선정한다. 기존 선택이 유효하면 유지한다.
2. 선택한 메시·재질·음원을 실제로 열어 외형·크기·충돌·재생·의존성을 확인한다. BP는 부모·컴포넌트·입력·단일 플레이어 가정을 확인한다.
3. 먼저 화물의 구분과 상호작용 표현을 연결하고, 해당 단계의 카메라·레이저·문·패널을 적용한다. 빠진 부품은 위 대체안으로 완성한다.
4. 상태에 맞는 사운드와 효과를 연결한다. 이후 조명·표지·주변 소품으로 가독성을 보완한다. 배경 장식 때문에 핵심 기능 구현을 미루지 않는다.
5. 수정한 BP 컴파일, 관련 자산 로드, 실제 테스트 맵 플레이를 확인한다. 관련 C++를 변경했다면 해당 빌드도 수행한다.
6. 멀티플레이 연결이 구현된 단계에서는 호스트와 클라이언트에서 화물 소멸, 카메라 경고, 레이저 켜짐, 문 상태, 음원 중복을 확인한다. 동시 사용·취소·재시작 시 상태와 연출이 남지 않아야 한다.
7. 외형 교체 후 통로·조준·시야 차단·탈출 영역이 유지되는지 확인한다. 4인 동시 효과와 조명 비용은 실제 실행 환경에서 점검하고, 측정하지 않은 성능을 보장하지 않는다.

| 기능 | 사용한 실제 원본 패키지 경로 | 프로젝트용 자산 경로 | 직접 제작·대체한 부분과 이유 | 수행한 검증 / 남은 항목 |
